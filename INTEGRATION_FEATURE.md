# Интеграция с Open Food Facts / Open Prices

## 📋 Описание

Реализована интеграция с внешним сервисом **Open Food Facts** для получения актуальных цен на продукты питания. Это позволяет автоматически обновлять цены в системе на основе реальных рыночных данных.

## 🎯 Зачем это нужно

### Проблема
- Ручное обновление цен трудоёмко и часто устаревает
- Цены в разных регионах и магазинах сильно отличаются
- Нет механизма автоматического получения актуальных данных

### Решение
- Подключение к Open Food Facts - крупнейшей открытой базе данных продуктов
- Автоматическая синхронизация цен с реальными рыночными данными
- Возможность привязки внутренних ингредиентов к внешним продуктам
- История цен с датами (как и требовалось в спецификации)

## 🏗️ Архитектура

### Бэкенд

#### Новые таблицы в БД

1. **integrations** - настройки подключений к провайдерам
   - `provider` - код провайдера (OFF)
   - `status` - статус подключения (DISCONNECTED/CONNECTED/ERROR)
   - `last_connected_at` - время последнего подключения
   - `last_sync_at` - время последней синхронизации
   - `error_message` - сообщение об ошибке

2. **external_products** - кэш внешних продуктов
   - `provider` - код провайдера
   - `external_code` - штрихкод продукта
   - `name` - название
   - `brand` - бренд
   - `pack_amount` - размер упаковки
   - `pack_unit` - единица измерения упаковки
   - `image_url` - URL изображения
   - `raw` - полные данные в JSONB

3. **sync_logs** - журнал синхронизаций
   - `provider` - код провайдера
   - `type` - тип синхронизации (CATALOG/PRICES)
   - `status` - статус (RUNNING/SUCCESS/FAILED)
   - `started_at` / `finished_at` - время начала/окончания
   - `created_count` / `updated_count` / `error_count` - статистика

4. **Обновления существующих таблиц**:
   - `ingredient_prices.source` - источник цены (MANUAL/OFF/API)
   - `ingredient_mappings.external_code` - внешний код продукта
   - `ingredient_mappings.external_product_id` - ссылка на внешний продукт

## 🔄 Процесс работы

### 1. Подключение
```
Пользователь → "Подключить" → POST /integrations/OFF/connect
                              ↓
                    OpenFoodFactsProvider.testConnection()
                              ↓
                    Проверка доступности API
                              ↓
                    Сохранение статуса CONNECTED
```

### 2. Привязка товара
```
Пользователь → Выбирает ингредиент → Вводит название → "Найти"
                                        ↓
                    GET /integrations/OFF/products/search?query=...
                                        ↓
                    OpenFoodFactsProvider.searchProducts()
                                        ↓
                    Возврат списка продуктов
                                        ↓
Пользователь → Выбирает продукт → "Привязать"
                                        ↓
                    POST /integrations/ingredients/{id}/mapping
                                        ↓
                    Создание IngredientMapping + ExternalProduct
```

### 3. Синхронизация цен
```
Пользователь → "Обновить цены" → POST /integrations/OFF/sync/prices
                                        ↓
                    Создание SyncLog (status=RUNNING)
                                        ↓
                    Получение всех маппингов с external_code
                                        ↓
                    Для каждого маппинга:
                      - OpenFoodFactsProvider.fetchPrices()
                      - Конвертация цены упаковки → цена единицы
                      - Фильтрация по валюте (только RUB)
                      - Сохранение в ingredient_prices (source=OFF)
                      - Обновление статистики
                                        ↓
                    Обновление SyncLog (status=SUCCESS/FAILED)
                                        ↓
                    Обновление last_sync_at в Integration
```

## 💰 Конвертация цен

### Формула
```
unitPrice = packPrice / packAmountInIngredientUnit
```

### Примеры

**Пример 1: Гречка**
- Внешний продукт: "Гречка", 900 г, 89.99 ₽
- Внутренний ингредиент: "Гречка", KG
- Конвертация: 900 г = 0.9 KG
- Цена за единицу: 89.99 / 0.9 = 99.99 ₽/KG

**Пример 2: Вода**
- Внешний продукт: "Вода питьевая", 1.5 L, 45 ₽
- Внутренний ингредиент: "Вода", L
- Конвертация: 1.5 L = 1.5 L
- Цена за единицу: 45 / 1.5 = 30 ₽/L

**Пример 3: Тушёнка**
- Внешний продукт: "Тушёнка говяжья", 325 г, 210 ₽
- Внутренний ингредиент: "Тушёнка", PCS
- Конвертация: несовместимые единицы (г → шт)
- Результат: цена не импортируется (требует ручной привязки)

### Правила
1. Конвертируем packAmount в единицы внутреннего ингредиента
2. Если единицы несовместимы (вес → штуки) - пропускаем
3. Фильтруем только валюту RUB
4. Не перезаписываем ручные цены (source=MANUAL)
5. Создаём новую запись или обновляем существующую с source=OFF

## 🛡️ Безопасность

### Защита ручных цен
```java
if (existingPrice.isPresent()) {
    IngredientPrice price = existingPrice.get();
    // Не перезаписываем ручные цены
    if (!"MANUAL".equals(price.getSource())) {
        price.setPricePerUnit(unitPrice);
        price.setSource(providerCode);
        priceRepository.save(price);
        updated++;
    }
}
```

### Валидация
- Проверка подключения перед синхронизацией
- Фильтрация по валюте (только RUB)
- Проверка корректности packAmount и packUnit
- Обработка ошибок для каждого маппинга отдельно

## 🚀 Использование

### Для администратора

1. **Первичная настройка:**
   - Подключить Open Food Facts
   - Привязать основные ингредиенты к внешним продуктам
   - Запустить первую синхронизацию

2. **Регулярное обновление:**
   - Периодически нажимать "Обновить цены"
   - Следить за журналом синхронизаций
   - Добавлять новые привязки по мере необходимости

3. **Ручная корректировка:**
   - Для критичных ингредиентов можно установить ручную цену
   - Ручные цены не перезаписываются при синхронизации
   - Источник цены отображается в системе

### Для пользователя

- Пользователь видит актуальные цены в расчётах
- Не нужно вручную обновлять цены
- Система автоматически использует последние данные
