# Provision — система планирования питания для походов

Веб-приложение для планирования питания в походах и яхтенных путешествиях: каталог продуктов и рецептов, планирование походов, расчёт закупок, стоимости и калорийности.

## Возможности

- **Каталог** — продукты и рецепты с калорийностью, ценой за единицу и размером упаковки
- **Походы** — планирование по дням и приёмам пищи, расчёт порций на человека
- **Закупки** — список покупок с округлением до упаковок, плановая и фактическая стоимость
- **Интеграции** — импорт продуктов из Open Food Facts
- **Аккаунты** — регистрация, JWT-авторизация, роль администратора

### Страницы приложения

| Маршрут | Что там |
|---|---|

| `/dashboard` | Обзор походов |

| `/recipes` | Каталог рецептов |
| `/integrations` | Импорт из Open Food Facts |
| `/admin`, `/sync-logs` | Администрирование и журнал синхронизации |

## Технологии

- **Frontend:** React 18 + TypeScript + Vite (раздаётся через nginx), порт **3000**
- **Backend:** Java 21 + Spring Boot 3.2.5, порт **8080**
- **База данных:** PostgreSQL 15 + Flyway (миграции применяются автоматически при старте бэкенда)

### Шаги

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/DesertDogFish/meal-provisioning-ai.git
   cd meal-provisioning-ai
   ```

2. Скопируйте пример окружения и задайте JWT-секрет (обязательно — без него бэкенд не стартует):
   ```bash
   cp .env.example .env
   # в .env замените JWT_SECRET на собственный, например:
   echo "JWT_SECRET=$(openssl rand -base64 48)" >> .env
   ```
   (Windows PowerShell: `$s=[Convert]::ToBase64String((1..48|ForEach-Object{Get-Random -Max 256})); Add-Content .env "JWT_SECRET=$s"`)

3. Запустите стек одной командой:
   ```bash
   docker compose up --build
   ```

4. Дождитесь, пока все сервисы станут `healthy` (обычно 2–3 минуты):
   ```bash
   docker compose ps
   ```

5. Откройте в браузере:
   - **Приложение:** http://localhost:3000
   - **Health-check API:** http://localhost:8080/api/v1/meta (вернёт JSON с `"db":"ok"`; при недоступной БД — HTTP 503)

### Первый запуск и создание пользователя

При первом запуске автоматически создаётся база данных, применяются миграции Flyway (V1–V11) и загружается стартовый каталог продуктов и рецептов (миграция `V3__seed_catalog.sql`).

Готовых учётных записей нет — первый пользователь создаётся через интерфейс:

1. Откройте http://localhost:3000
2. Нажмите «Регистрация» и заполните форму
3. Войдите — можно создавать продукты, рецепты и походы, генерировать списки покупок

API-документация доступна после запуска: http://localhost:8080/swagger-ui.html

### Переменные окружения

Все настройки берутся из `.env` (файл не коммитится, шаблон — `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTGRES_PASSWORD` | `provision123` | Пароль БД (для локальной разработки допустимо, для публичного хоста — смените) |
| `JWT_SECRET` | **обязательна**, значения по умолчанию нет | Подпись JWT-токенов. Без неё compose/бэкенд упадут с понятной ошибкой (fail-fast). Минимум 32 символа; генерация: `openssl rand -base64 48` |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:3000` | Разрешённые origins для прямых запросов к API (разработка без nginx-прокси). В Docker-стеке не требуется |
| `VITE_API_URL` | `/api/v1` в Docker-сборке | Адрес API; подставляется **при сборке** фронта (build-arg), не в рантайме |
| `VITE_API_MODE` | `real` в Docker-сборке | Режим фронтенда: `auto` / `api` / `mock` |

Порт PostgreSQL проброшен только на `127.0.0.1:5432` — из локальной сети база недоступна.

В Docker-стеке фронт обращается к API через nginx-прокси (`/api/` → backend), поэтому браузер работает без CORS. Приоритет выбора режима: переключатель в UI (localStorage) → `VITE_API_MODE` → авто-пинг `GET /api/v1/meta`.

### Остановка и очистка

```bash
docker compose down      # остановить сервисы (данные сохраняются)
docker compose down -v   # полная очистка, включая базу данных
```

### Частые проблемы

| Симптом | Что делать |
|---|---|
| backend долго не становится `healthy` | `docker compose logs backend` — ошибки подключения к БД или миграций |
| фронт отдаёт страницу, но данные не грузятся | проверить `curl http://localhost:8080/api/v1/meta`, затем `docker compose logs frontend` |
| порт 3000/5432/8080 занят другим приложением | поменяйте хостовую часть в `ports:` в `docker-compose.yml` |
| нужна чистая БД после сбоя миграций | `docker compose down -v && docker compose up --build` |
