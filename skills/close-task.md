# Skill: закрыть задачу + формат отчёта

## Порядок закрытия (дешёвые операции, по шагам)

1. Все чекбоксы подзадач `[x]` (или Status: CANCELLED с причиной в «Результатах»).
2. Заполни секцию `## Результаты` в файле задачи — честно:
   - что сделано (по подзадачам, 1 строка на каждую);
   - что ПРОВЕРЕНО: команды и числа («vitest 935/935», «SnapshotIsolation 3/3»);
   - что НЕ проверено и почему («нет Docker-демона», «лимит памяти», «нет gh — CI не проверен»);
   - отклонения от плана и решения, которые стоит подтвердить владельцу.
3. Шапка: `Status: DONE`, `Closed: YYYY-MM-DD`.
4. Документация по карте R11 обновлена в тех же правках (`skills/docs-sync.md`).
5. Перенос (единственная «дорогая» операция — и это просто mv):
   ```bash
   mkdir -p tasks/done/$(date +%Y-%m)
   git mv tasks/<имя>.md tasks/done/$(date +%Y-%m)/
   ```
6. Файлы в `tasks/done/` больше НЕ редактируются никогда. Нашёл ошибку в закрытом —
   новая задача/пачка багов со ссылкой на файл в done.

## Частичное закрытие
Пачка багов: закрытые баги остаются отмеченными `[x]` в том же файле; файл уезжает в
done только когда закрыт целиком. Недоделанный остаток — новая подзадача/файл со
ссылкой на предшественника (частично закрытые записи в живых задачах не живут).

## Формат финального отчёта пользователю (обязателен)

```
Workflow run: <URL или «нет, CI не проверено»>
backend: passed/failed (числа прогонов; тяжёлые сьюты — «не запускались, лимит памяти»)
frontend: passed/failed (lint/typecheck/vitest/build — что реально гонял)
docker: passed/failed/«нет демона — не проверялось»
security: passed/warning/failed
test: passed/failed

<3–5 строк: что сделано, что проверено, что осталось/риски>
```

Запрещено: «всё готово, можно мержить» без чисел и ссылок; приписывать гейты, которые
не прогонял; дублировать текст задачи вместо результатов.

## Коммит
ТОЛЬКО по прямой просьбе пользователя. До просьбы — изменения остаются в рабочем дереве.
