# Skill: починить баг

## Порядок (не пропускать шаги)

1. **Запиши баг** в файл-задачу (`skills/create-task.md`): открытая пачка багов в
   `tasks/` или подзадача тематической задачи. Нет файла — создай. Без записи код не правим.
2. **Воспроизведи**: найди минимальный сценарий. Не воспроизводится — запиши в карточку
   «не воспроизводится, нужно <что>» и спроси пользователя; не чини вслепую.
3. **RED**: напиши падающий тест на том же слое, где баг (R2):
   - логика/сервис → unit (Mockito / vitest);
   - HTTP-контракт → integration (MockMvc) / contract-тест;
   - UI → component-тест (testing-library).
   Запусти — тест ОБЯЗАН падать по правильной причине (команды: `skills/testing.md`).
4. **GREEN**: минимальный фикс. Фикс-тикет меняет поведение только в рамках дефекта —
   новая архитектура запрещена (отдельная задача).
5. **Проверь**: тот же тест зелёный + прогон соседних тестов файла/модуля + гейты
   (`skills/testing.md` → «Гейты»).
6. **Документация**: если поведение описано в доках — правь в той же сессии
   (`skills/docs-sync.md`, карта R11).
7. **Отметь** чекбокс подзадачи в файле-задаче `[x]` и допиши в «Заметки» одну строку:
   что было, что стало, каким тестом защищено. Всё — дорогие операции не нужны.

## Запрещено
- Глушить тест (`@Disabled`, `it.skip`) без TODO-комментария со ссылкой на файл-задачу (R4).
- Утверждать «починено» без зелёного прогона (R6) — сначала прогони, потом пиши.
- Чинить попутно другие баги в том же прогоне — заведи подзадачи в пачке.

## Баг в уже закрытой задаче?
Не редактируй `tasks/done/` — создай/дополни активную пачку багов и сошлись на файл
в `tasks/done/` как источник.
