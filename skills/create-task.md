# Skill: создать задачу

## Когда
- Пользователь дал новую работу (> 1 файла правок).
- Найден баг, а открытой пачки багов нет → создай пачку (см. ниже).
- Идея «на потом» — тоже задача-файл (Status: READY). Никаких общих реестров!

## Куда
`tasks/<короткое-имя>.md` — латиница, дефисы, без даты в имени активных задач.
`ls tasks/` — это и есть индекс активных задач. Сначала посмотри его: если есть
похожая тема — добавь подзадачу туда, не плоди файлы.

## Форматы (два, других нет)

### 1. Обычная задача (подзадачи ≤ 10)
```markdown
# Задача: <название>

Status: READY            # READY → IN_PROGRESS → DONE / CANCELLED
Created: YYYY-MM-DD
Closed:

## Цель
1–3 строки: что и зачем.

## Подзадачи
- [ ] 1. <что сделать> — файлы: <список>; приёмка: <как проверить>
- [ ] 2. ...

## Заметки
(решения, находки, баги по ходу — буллетами)

## Результаты (заполнить при закрытии)
```

### 2. Пачка багов (1–10 багов в файле)
Имя: `tasks/bugs-<тема>.md`. Тот же формат, но подзадачи — баги:
```markdown
- [ ] BUG: <симптом одной строкой>. Файлы: <где>. Приёмка: <red→green тест + проверка>.
```
Пачка заполнилась (10) или закрыта → новая пачка отдельным файлом.

## Правила
- Один файл = одна работающая единица. Закрытие = `git mv` файла в `tasks/done/<YYYY-MM>/`
  (см. `close-task.md`) — никаких правок чужих больших файлов.
- В задаче НЕ пересказывать архитектуру — ссылка на `ARCHITECTURE.md`/скилл.
- Старые номера `BL-n`/`KB-n` из расформированных реестров сохранены в карточках задач —
  не переиспользуй и не выдумывай новые сквозные номера; идентификатор = имя файла + номер подзадачи.
- Большие задачи (≥ 5 файлов): сначала файл со Status: READY, показать пользователю,
  код — только после подтверждения (планирование и реализация — разные сессии).
