# AGENTS.md — правила для AI-агентов (короткий; детали — в `skills/`)

Проект: планировщик питания для походов (React+TS / Spring Boot / PostgreSQL).
Запуск и стек — `README.md`; контракты и формулы — `ARCHITECTURE.md`; дизайн —
`provisions/design-pack/`.

## Золотые правила (нарушил = работа переделывается)

1. **Не коммить и не пушь без прямой просьбы пользователя.** Ты помощник, не автономный
   агент: решения прозрачны, проверяемы, обратимы; последнее слово за пользователем.
2. **Сначала задача — потом код.** Вся работа ведётся в файле-задаче в `tasks/`
   (нет файла — создай: `skills/create-task.md`). `ls tasks/` — индекс активных задач;
   отдельного индекса нет и не заводи.
3. **Реестров больше нет.** `plans/backlog.md`, `plans/knownbugs.md`, `PLAN.md` — заглушки
   (расформированы 02.11.2026). Баги = подзадачи в пачке `tasks/bugs-*.md` (1–10 на файл).
4. **Закрытие = перенос файла**, а не правка общих документов:
   `git mv tasks/<имя>.md tasks/done/<YYYY-MM>/` (`skills/close-task.md`).
   Файлы в `tasks/done/` не редактируются НИКОГДА.
5. **Red → Green**: баг сначала воспроизводится падающим тестом (`skills/fix-bug.md`).
6. **Не утверждай без прогона** (R6): «зелено», «прошло», «CI ок» — только с числами из
   реального запуска. Не запускал — так и напиши. Команды: `skills/testing.md` (копируй, не изобретай).
7. **Документы — в той же сессии, что код** (карта R11: `skills/docs-sync.md`).
   Новые MD — только из белого списка там же.
8. **Кодировка**: все файлы UTF-8 с кириллицей. Читать/писать только UTF-8 инструментами
   (Python `open(..., encoding='utf-8')`, штатные tools). PowerShell `type`/`Get-Content`/
   `Out-File` запрещены (дают mojibake/cp1252).

## Workflow для больших задач (≥ 5 файлов)

1. Сессия 1: оформить файл задачи (`Status: READY`), показать пользователю, код НЕ писать.
2. Сессия 2+: «Прочитай `tasks/<имя>.md`, выполни подзадачу N, обнови чекбокс и Заметки».
   Каждая подзадача — чистый контекст; в задаче хранятся решения и прогресс (внешняя память).
3. Финал: `skills/close-task.md`.

Фиксы на 1–3 файла — без отдельного планирования, но с записью в пачку багов/задачу.

## Грабли окружения (Windows + git-bash): обходить сразу

1. **Maven запускать через `cmd.exe`.** Bash-обёртка `mvn` из PATH падает
   `ClassNotFoundException: org.codehaus.plexus.classworlds.launcher.Launcher`
   (класс-мир не подхватывается из `lib/`). Рабочий вид:
   `cmd.exe /c "mvn -B -o test -DforkCount=0 -Dtest=ИмяКласса -DfailIfNoSpecifiedTests=false"`.
   Симптом «Maven не стартует» — это не проект и не pom.
2. **Переменные из `.env` не подхватываются сами.** Spring падает на старте
   `IllegalStateException: JWT_SECRET is not set` (`JwtProperties.validate`) → все тесты
   класса красные «не по коду». Перед прогоном бэкенд-тестов:
   `set -a; . ../.env; set +a` (из каталога `backend/`), затем `cmd.exe /c "mvn ..."`.

## Прочее

- GitHub Actions: SHA для actions — только из официальных релизов (придуманные запрещены);
  предпочтительны теги (`@v4`). Новые шаги с внешними зависимостями — с фолбэками.
- CI: не мержить при красном CI по своей вине; non-blocking падения разбираются задачами в `tasks/`.
- Фикс-тикет не меняет архитектуру (новые сущности/эндпоинты/слои — отдельная задача).
- Старые ссылки: «AGENTS.md §N» и реестры `BL-n`/`KB-n` в комментариях кода и архивах —
  дореформенный формат (до 02.11.2026); прежний AGENTS.md — в истории git. Пути `plans/done/<файл>`
  и `plans/2026-11-02-…` в комментариях кода указывают на файлы, перенесённые в
  `tasks/done/2026-10/` и `tasks/done/2026-11/` (имя файла не изменилось); комментарии кода
  при этом НЕ массово правятся — это историческая атрибуция.
- Владелец репозитория — DesertDogFish. Архитектурные споры фиксируются в файле задачи до реализации.
