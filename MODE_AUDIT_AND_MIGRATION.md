## 🏗️ Архитектура режимов

### Режимы работы

| Режим | Поведение при недоступности API | Поведение при доступном API |
|-------|--------------------------------|----------------------------|
| **AUTO** (дефолт) | Переключение на мок + видимое предупреждение | Работаем с API |
| **FORCE_API** | Никакого мока: экраны показывают error-состояние с ретраем | Работаем с API |
| **FORCE_MOCK** | Мок | Мок, сетевые запросы к /api/v1 не выполняются вообще |

### Детект в AUTO
- Пинг `GET {VITE_API_URL}/api/v1/meta`
- Таймаут 700 мс
- Результат кешируется на сессию

### Watchdog
- В AUTO и FORCE_API повторный пинг каждые 60 с
- Переход REAL→недоступен: фолбэк на мок + предупреждение
- Переход мок→доступен: тост «API снова доступен» с кнопкой «Переключиться на API»

### Смена режима
- `queryClient.cancelQueries()` + `queryClient.clear()` + `refetch` всего
- Никаких смешанных данных на экране

### Персист
- `localStorage.apiMode ∈ {auto, api, mock}`
- Переживает перезагрузку (MODE-08)
- `VITE_API_MODE` задаёт начальное значение, но не блокирует ручной выбор

## 🎨 Бейдж-индикатор

### Состояния

| Состояние | Вид | Текст |
|-----------|-----|-------|
| REAL | зелёная точка | «бэкенд: подключён» |
| AUTO→мок после фолбэка | янтарная точка + пульс первые 5 с | «демо-данные: API недоступен» |
| FORCE_MOCK | янтарный контур | «демо-данные: ручной режим» |
| FORCE_API + ошибка | красная точка | «бэкенд: ошибка» |

### Модалка (клик по бейджу)
- Текущий режим и причина авто-решения
- Радио-переключатель режимов: Авто / Всегда API / Всегда мок
- Кнопка «Проверить соединение»
- Блок последней ошибки
- «Сбросить демо-данные»

## 🚨 Видимость фолбэка

### В AUTO при падении на мок
- Баннер-тост на 8 с + постоянная янтарная точка бейджа
- В баннере: причина (ECONNREFUSED / 404 / timeout), кнопка «Повторить» и ссылка на модалку бейджа

### В FORCE_API при недоступности
- Мока нет нигде — каждый экран в error-состоянии с текстом причины и ретраем
- Бейдж красный

### Логирование
- Событие фолбэка пишется в консоль (`console.warn`)
- В `sessionStorage.lastFallback` — для отладки и тестов

## 📝 Контракт мока

Mock-сервер продолжает реализовывать маршруты и формы ответов ТЗ один в один:
- `{items,…}`, `unitLabel`, `planned/actual`, `details` синков
- Задержки 200–400 мс
- `?fail=<route>` для error-состояний
- Числа FIX-1/FIX-2 совпадают с бэкенд-тестами
