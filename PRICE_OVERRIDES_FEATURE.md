# Фича: Оверрайды цен похода (Price Overrides)

## 📋 Описание

Реализована возможность установки фактических цен на ингредиенты для конкретного похода. Это позволяет учитывать реальные цены из чеков, которые могут отличаться от плановых цен в справочнике.

## 🎯 Зачем это нужно

### Проблема
- Плановые цены в справочнике могут устареть
- Реальные цены в разных магазинах отличаются
- Нужно точно знать, сколько потрачено в конкретном походе
- Нужно сравнивать план с фактом

### Решение
- Оверрайды цен хранятся отдельно от справочника
- Один оверрайд действует на весь поход (на все дни)
- Плановые цены не изменяются
- Можно сравнивать план с фактом и видеть дельту

## 🏗️ Архитектура

### Модель данных

#### Таблица `trip_price_overrides`
```sql
CREATE TABLE trip_price_overrides (
    id BIGSERIAL PRIMARY KEY,
    trip_id BIGINT NOT NULL REFERENCES trips(id) ON DELETE CASCADE,
    ingredient_id BIGINT NOT NULL REFERENCES ingredients(id) ON DELETE CASCADE,
    actual_price NUMERIC(14,2) NOT NULL CHECK (actual_price >= 0),
    currency VARCHAR(3) NOT NULL DEFAULT 'RUB',
    comment VARCHAR(500),
    updated_by BIGINT REFERENCES users(id),
    updated_at TIMESTAMP NOT NULL DEFAULT now(),
    UNIQUE (trip_id, ingredient_id)
);
```

**Ключевые моменты:**
- Один оверрайд на ингредиент на поход (UNIQUE constraint)
- Оверрайд действует на весь поход (не привязан к дням)
- При удалении похода оверрайды удаляются каскадно
- Хранится кто и когда изменил цену

### Правила разрешения цен

**PriceResolutionService** - единственная точка принятия решения:

```java
PriceResolution resolvePrice(Long tripId, Long ingredientId, LocalDate date) {
    Optional<BigDecimal> actualPrice = getActualPrice(tripId, ingredientId);
    Optional<BigDecimal> plannedPrice = getPlannedPrice(ingredientId, date);
    
    return new PriceResolution(
        plannedPrice.orElse(null),
        actualPrice.orElse(plannedPrice.orElse(null)),
        actualPrice.isPresent(),
        plannedPrice.isPresent()
    );
}
```

**Логика:**
1. Если есть оверрайд → используем его (фактическая цена)
2. Если нет оверрайда → используем плановую цену на дату дня
3. Если нет ни того, ни другого → цена отсутствует (missing)

### Формулы расчёта

**Для каждого ингредиента в дне:**
```
plannedCost = amount × plannedUnitPrice
actualCost = amount × (overridePrice ?? plannedUnitPrice)
```

**Для всего похода:**
```
totalPlannedCost = Σ plannedCost по всем дням и ингредиентам
totalActualCost = Σ actualCost по всем дням и ингредиентам
deltaPercent = (totalActualCost - totalPlannedCost) / totalPlannedCost × 100
```

## 🔌 API

### Endpoints

```
GET    /api/v1/trips/{tripId}/price-overrides
PUT    /api/v1/trips/{tripId}/price-overrides/{ingredientId}
DELETE /api/v1/trips/{tripId}/price-overrides/{ingredientId}
```

### Примеры запросов

**Получить все оверрайды:**
```bash
GET /api/v1/trips/1/price-overrides
```

**Создать/обновить оверрайд:**
```bash
PUT /api/v1/trips/1/price-overrides/5
Content-Type: application/json

{
  "ingredientId": 5,
  "actualPrice": 250.00,
  "comment": "По чеку из Пятёрочки"
}
```

**Удалить оверрайд:**
```bash
DELETE /api/v1/trips/1/price-overrides/5
```

## 🎨 UI

### Новая вкладка "Закупка и чеки"

**Расположение:** TripDetailPage → вкладка "Закупка и чеки"

**Функциональность:**

1. **Sticky итог сверху:**
   - План (всего)
   - Факт (всего)
   - Дельта в процентах

2. **Таблица с колонками:**
   - Продукт
   - Кол-во
   - План ₽/ед
   - План ₽
   - Факт ₽/ед (inline-edit)
   - Факт ₽
   - Δ (дельта в %)
   - Действия (редактировать/удалить)

3. **Inline-редактирование:**
   - Клик по иконке редактирования → input для цены
   - Enter или клик на ✓ → сохранить
   - Esc или клик на ✗ → отмена

4. **Цветовая индикация дельты:**
   - Факт > план → янтарный чип "+12%"
   - Факт < план → зелёный чип "−4%"
   - Факт = план → серый чип "0%"

## 📊 Пример расчёта (FIX-2)

**Входные данные:**
- Поход: 12-14 мая
- Люди по дням: 4 / 3 / 2 (totalPersonMeals = 13)
- Рецепт: Гречка с тушёнкой (baseServings = 4)
  - Гречка: 0.8 KG
  - Тушёнка: 4 PCS
  - Соль: 0.02 KG

**Оверрайды:**
- Гречка: факт 250₽ (план 200₽)
- Тушёнка: факт 190₽ (план 210₽)
- Соль: факт 30₽ (плана нет)

**Расчёт по дням:**

| День | Люди | Гречка | Тушёнка | Соль | Итого |
|------|------|--------|---------|------|-------|
| 12 мая | 4 | 0.8 KG | 4 PCS | 0.02 KG | - |
| 13 мая | 3 | 0.6 KG | 3 PCS | 0.015 KG | - |
| 14 мая | 2 | 0.4 KG | 2 PCS | 0.01 KG | - |
| **Итого** | **13** | **1.8 KG** | **9 PCS** | **0.045 KG** | - |

**Стоимость:**

| Компонент | Кол-во | План/ед | План ₽ | Факт/ед | Факт ₽ |
|-----------|--------|---------|--------|---------|--------|
| Гречка | 1.8 KG | 200 | 360.00 | 250 | 450.00 |
| Тушёнка | 9 PCS | 210 | 1890.00 | 190 | 1710.00 |
| Соль | 0.045 KG | — | missing | 30 | 1.35 |
| **Итого** | | | **2250.00** | | **2161.35** |

**Дельта:** (2161.35 - 2250) / 2250 × 100 = **-3.94%**

**На человека (факт):**
- На 1 чел: 2161.35 / 4 = **540.34₽**
- На 1 чел/приём: 2161.35 / 13 = **166.26₽**

## 🔒 Безопасность

### Права доступа
- Только владелец похода может управлять оверрайдами
- Админ может управлять оверрайдами любых походов
- Другие пользователи видят только свои походы

### Валидация
- `actualPrice >= 0` (не отрицательная)
- `scale <= 2` (не более 2 знаков после запятой)
- `currency = 'RUB'` (только рубли)

### Изоляция
- Оверрайды не влияют на справочник цен
- Оверрайды не влияют на другие походы
- Синхронизация с OFF не затрагивает оверрайды

## 🚀 Использование

### Сценарий 1: Ввод цен по чеку

1. Открыть поход
2. Перейти на вкладку "Закупка и чеки"
3. Для каждого ингредиента:
   - Кликнуть на иконку редактирования
   - Ввести фактическую цену из чека
   - Добавить комментарий (например, "Пятёрочка, 15 мая")
   - Нажать ✓ или Enter

### Сценарий 2: Сравнение плана с фактом

1. Открыть вкладку "Закупка и чеки"
2. Посмотреть на sticky-итог сверху:
   - План: 2250₽
   - Факт: 2161₽
   - Дельта: -3.94%
3. Посмотреть на таблицу:
   - Зелёные чипы "−4%" → сэкономили
   - Янтарные чипы "+12%" → переплатили

### Сценарий 3: Удаление оверрайда

1. Найти ингредиент с оверрайдом
2. Кликнуть на иконку корзины
3. Подтвердить удаление
4. Фактическая цена вернётся к плановой

## 📈 Преимущества

1. **Точность:** учитываем реальные цены из чеков
2. **Гибкость:** можно корректировать цены для каждого похода
3. **Прозрачность:** видно дельту между планом и фактом
4. **Изоляция:** оверрайды не влияют на справочник
5. **Удобство:** inline-редактирование без модальных окон
