## Цель
Плюс создания похода — на месте как у всех страниц, в kebab карточки есть
«Отчёт», прогресс-бар честно отражает самый ранний незакрытый этап.

## Подзадачи

- [x] 1. BUG: на мобильном плюс «Создать поход» утекает вниз страницы —
  `.trips-fab` в `@media (max-width: 767px)` делает кнопку `position: fixed;
  bottom: 74px` (FAB). Владелец: должен быть справа вверху, как на остальных
  страницах (Продукты/Блюда — иконочная кнопка в шапке).
  Файлы: `src/index.css` (~строки 1327–1342: удалить блок `.trips-fab` и
  компенсацию `.trips-list { padding-bottom }`), `src/pages/TripsPage.tsx`
  (~строка 325: класс `trips-fab` можно оставить пустым или убрать).
  Приёмка: RED — e2e/визуально: на viewport 360×640 кнопка внутри шапки
  (не fixed внизу); в песочнице Playwright не стартует — приёмка через
  компонентный тест (`TripsPage.create.test.tsx`: кнопка — потомок шапки,
  без класса позиционирования) + проверка CI e2e `mobile.spec.ts`; GREEN —
  после удаления CSS-оверрайда.

- [x] 2. BUG: в kebab карточки похода только «Редактировать»/«Удалить» — нет
  «Отчёт» (показ финального отчёта). Файлы: `src/pages/TripsPage.tsx`
  (~строки 385–405, items kebab'а): добавить пункт `{ id: 'report',
  label: 'Отчёт', icon: <FileDown/>, onSelect: () => navigate(`/trips/${trip.id}/report`) }`
  с testId `trip-report-${trip.id}`.
  Приёмка: RED — новый кейс (в `TripsPage.create.test.tsx` или отдельный):
  в kebab карточки есть пункт «Отчёт», клик ведёт на /trips/:id/report —
  падает; GREEN — после добавления.
  Связь: после внедрения `tasks/trip-workflow-redesign.md` (этап ⑤) пункт
  должен вести на `?stage=ready` (или /report с редиректом) — согласовать при
  реализации, чтобы не править дважды.

- [x] 3. BUG: прогресс-бар карточки «считается по нарастающей»: `buildProgressMap`
  выбирает этап по самому продвинутому признаку (`checks !== 'none' || facts>0`
  → этап ④ и т.д.), поэтому при введённых чеках и незакрытой закупке/магазине
  полоса выглядит заполненной. Считать по нижней (самой ранней незакрытой)
  части воркфлоу: menu не готов → ①; иначе checklist пуст → ②; иначе store не
  done → ③; иначе checks не done → ④; иначе «Готов». done/total — по выбранному
  этапу. Файлы: `src/pages/TripsPage.tsx` (`buildProgressMap`, ~строки 58–100),
  `src/utils/readiness.ts` (при необходимости — общая функция «текущий этап»
  вместо локальной логики, чтобы страница похода и список не разъехались).
  Приёмка: RED — кейс в `src/pages/TripsPage.progress.test.tsx`: facts>0,
  bought<checklistTotal → stage='store' (или 'shopping'), полоса НЕ полная —
  падает на текущей логике; GREEN — после фикса; существующие кейсы прогресса
  обновить под новую семантику (зафиксировать в Заметках результаты).

- П.3 взаимодействует с `tasks/trip-workflow-redesign.md`: там модель

  `skills/testing.md`.
